Everything you configure lives in a single `RegattaCluster` resource. This page covers the object header, RegattaDB image, Pod layout, and per-module settings. See [Storage](./storage.mdx), [Networking](./networking.mdx), [Security & Lifecycle](./security-and-lifecycle.mdx), and [Resources & Scheduling](./resources-and-scheduling.mdx) for the rest of the spec.

## A minimal RegattaCluster resource

```yaml
apiVersion: regatta.dev/v1alpha1
kind: RegattaCluster
metadata:
  name: my-regattadb
  namespace: <namespace>
spec:
  image:
    repository: registry.example.com/regatta
    tag: "<version>"
  rdb:
    blockStorage:
      size: 60Gi
  repoStorage:
    size: 5Gi
  logs:
    size: 5Gi
```

`spec.image`, `spec.rdb`, `spec.repoStorage`, and `spec.logs` are required. This example uses the default `Legacy` layout with one RDB replica. See [Quickstart: Single-Node RegattaCluster](../examples/quickstart-single-node.mdx) for an end-to-end walkthrough.

## Configure the object header

| Field | Description |
| --- | --- |
| `apiVersion` | `regatta.dev/v1alpha1` |
| `kind` | `RegattaCluster` |
| `metadata.name` | A unique, DNS-compatible name. For every Pod group in your layout, `<cluster>-<group>` must be a DNS label of at most 52 characters |
| `metadata.namespace` | The namespace where you installed the operator |

## Configure the image

| Field | Required/default | Description |
| --- | --- | --- |
| `spec.image.repository` | Required | The RegattaDB image repository in your registry |
| `spec.image.tag` | Required unless `digest` is set | An image tag |
| `spec.image.digest` | Required unless `tag` is set | An immutable image digest, for example `sha256:...`; prefer this for production |
| `spec.image.pullPolicy` | `IfNotPresent` | `Always`, `IfNotPresent`, or `Never` |
| `spec.image.pullSecrets` | Optional | Names of image-pull Secrets in your namespace, for a private image repository |

You can change `spec.image` after creation. This updates the workload image and triggers a Kubernetes StatefulSet rollout, which replaces Pods one at a time within each group. A single-Pod group has no other replica to serve during its restart. An image update is not a migration procedure; see [Upgrading from 26.4.x](../operations.mdx#upgrading-from-264x).

## Configure Pod placement

Set `spec.layout` to `Legacy`, `Distributed`, or `AllInOne`. See [Deployment Architecture](../introduction.mdx#deployment-architecture) for the modules and Pod groups in each layout. If you omit `spec.layout`, the operator uses `Legacy`. Set `spec.rdb.replicas` to choose the number of RDB replicas; it defaults to `1` and must be `1` with `AllInOne`.

You cannot change the layout or replica count after creating the resource. To change either, plan a new cluster and a separate data migration. Separate Pod groups do not imply separate Kubernetes nodes; use [Schedule Pods](./resources-and-scheduling.mdx#schedule-pods) to control that placement.

## Configure module settings

RegattaDB has six modules: SM, SNA, Sequencer, GDD, DCM, and RDB. Each has its own `spec.<module>` section with the same fields:

| Field | Required/default | Immutable | Description |
| --- | --- | --- | --- |
| `port` | Module default (see table below) | Yes | The RegattaDB process port. Change it only if your release requires a different port. The operator's generated Kubernetes Service exposes it alongside `service_port` |
| `service_port` | Module default (see table below) | Yes | RegattaDB's own internal service port for the module, used for internal service operations |
| `num_threads` | Optional | Yes | The module's thread allocation. If set, `spec.resources` must cover it (see [Resources & Scheduling](./resources-and-scheduling.mdx)) |
| `ram_MB` | Optional | Yes | The module's memory allocation in megabytes. If set, `spec.resources` must cover it |
| `config` | `{}` | No | RegattaDB module settings as string key/value pairs. Every value must be a string, even for numbers or booleans, for example `"1"` rather than `1` |

Default ports:

| Module | `port` | `service_port` |
| --- | ---: | ---: |
| SM | 8840 | 5000 |
| SNA | 8841 | 5001 |
| Sequencer | 8842 | 5002 |
| GDD | 8843 | 5003 |
| DCM | 8844 | 5004 |
| RDB | 8850 | 6001 |

If you override ports, make sure that modules sharing a Pod do not use conflicting ports. Modules in separate Pods can reuse ports.

## RegattaCluster examples

`config/examples/` in the release package includes:

- `regatta-minimal.yaml`: the smallest example, shown above.
- `regatta-full.yaml`: a comprehensive `Legacy` example. Use it as a field-by-field reference, not as sizing guidance.
- `regatta-all-in-one.yaml` and `regatta-all-in-one-full.yaml`: minimal and full `AllInOne` examples.
- `regatta-distributed.yaml` and `regatta-distributed-full.yaml`: minimal and full `Distributed` examples.
- `regatta-static-storage.yaml`: uses pre-created `PersistentVolumes` for RDB block storage instead of a `StorageClass`, with more than one raw block device per RDB Pod. See [Example: Two Local NVMe Devices, One RDB Replica](../examples/static-storage-local-nvme.mdx) for a full walkthrough.
