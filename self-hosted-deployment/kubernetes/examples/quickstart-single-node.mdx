This page walks you through creating your first `RegattaCluster` resource. Make sure you've completed [Installation](../installation.mdx) first: the operator must already be running in your cluster.

## 1. Create a RegattaCluster resource

Use the `Legacy` layout with one RDB replica. It runs SM, SNA, DCM, GDD, and Sequencer in one Pod, and RDB and its own SNA in another. Both Pods can run on the same Kubernetes node.

```yaml
apiVersion: regatta.dev/v1alpha1
kind: RegattaCluster
metadata:
  name: my-regattadb
  namespace: <namespace>
spec:
  layout: Legacy
  image:
    repository: registry.example.com/regatta
    tag: "<version>"
  rdb:
    blockStorage:
      size: 60Gi
  repoStorage:
    size: 5Gi
  logs:
    size: 5Gi
```

Use `config/examples/regatta-minimal.yaml` as a starting point and update the name, namespace, and image for your deployment. `Legacy` and one RDB replica are the defaults. If your default `StorageClass` does not support raw block volumes, choose a block-capable class for `spec.rdb.blockStorage.storageClassName`. The SM Pod requests 4 CPUs and 2Gi of memory by default, and the RDB Pod requests 4 CPUs and 16Gi. Make sure your node has enough allocatable capacity for both Pods. See [Configuration Overview](../configuration/overview.mdx) and [Storage](../configuration/storage.mdx) for the full settings.

## 2. Apply and verify

```sh
kubectl -n <namespace> apply -f config/examples/regatta-minimal.yaml
kubectl -n <namespace> get rgc
kubectl -n <namespace> get rgc my-regattadb -o yaml
```

You can also list every resource the operator generated in one command. With `Legacy` and one RDB replica, you should see two StatefulSets (`my-regattadb-sm` and `my-regattadb-rdb`) and two Pods (`my-regattadb-sm-0` and `my-regattadb-rdb-0`):

```sh
kubectl -n <namespace> get statefulsets,services,configmaps,secrets,pods,pvc \
  -l app.kubernetes.io/instance=my-regattadb
```

<Note>
  A new `RegattaCluster` resource does not become `Ready` immediately: Kubernetes must provision storage and start Pods before the operator can configure and start RegattaDB through the System Manager. Track `status.conditions` (see [Reading RegattaCluster Status](../operations.mdx#reading-regattacluster-status)) until you see `Ready` reported as `True`, rather than expecting readiness right away.
</Note>
